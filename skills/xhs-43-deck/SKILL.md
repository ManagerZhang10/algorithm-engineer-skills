# 小红书 4:3 配图 deck

一篇小红书图文 = 一段正文 + 几张图。这个技能出的是那几张图：每页 1440×1080，
上面一行标题，下面一张白卡占满，图在白卡里自绘（SVG）。手机上图片按屏宽显示，约 920px 宽，
所以 1440 画布上的 28px 到手机上只剩约 18px——**所有规矩都是为了在手机上不放大也看得清**。

能力在脚本里，这里只写判断。脚本用法和 helper 清单见 [references/api.md](references/api.md)，
写第一页之前读一遍。

## 快速开始

```bash
python3 <本技能>/scripts/xhs43.py new path/to/my-post     # 复制库 + 示例 build.py + 文案.md 模板
cd path/to/my-post
python3 build.py --png          # 生成 deck.html + png/01_xxx.png…，并自动做手机字号自查和文案字数检查
python3 build.py --png 2        # 只重出第 2 页
python3 build.py --png --open   # 出图、自查后把整套 PNG 打开给用户看
```

- `new` 会把 `xhs43.py` 复制进项目目录，deck 自包含，之后技能升级不会改坏旧 deck。
- 示例 `build.py` 有 3 页：公式页、3 行对比页、HTML 表格页，改的时候从最像的那页复制。
- 依赖：Python 3 标准库，本机 Chrome / Chromium / Edge（找不到时用环境变量 `CHROME=` 指定）。

## 1. 流程

按这个顺序，**每一步都先和用户对齐再往下走**：

1. **先定文案**。正文写进 `文案.md`：开头两三句给结论，然后用「`01 ·`」「`02 ·`」……逐段对应第 1、2…张图，
   一段讲一张图。文案没定之前不画图。
2. **逐页对齐画图想法**。每页先用文字草图跟用户确认：标题一行写什么、白卡里画什么、哪几个数字最大、
   结论放哪一行。用户点头后再写画图函数。
3. **出图**：`python3 build.py --png`。
4. **机械自查**：看终端的字号表。脚本会查三件事——图内最小字号（按 1440 宽和手机约 920 宽各报一遍）、
   文字出了白卡、两段文字互相压住，再加标题一行放不下。有 ✗ 的页改完重出，直到全部 ✓。
   再用 Read 逐张打开 PNG 看一眼有没有画错位的线和框。
5. **口味预审**（本机装了 `taste-judge` 时做，没有就跳过）：
   `taste-judge --kind xhs_figure png/*.png --copy <文案.md> --intent "<这篇想讲清的一句话>"`。
   先修否决项，再按修改单的优先级改，只重出改过的页，最多 3 轮；结论到「可以给他看」或跑满 3 轮就停。
   要用户拍板的修改（换比喻、换 case、删他确认过的内容、事实拿不准）不自己改，交图时带着问他。
6. **交给用户审**：`python3 build.py --png --open` 把整套 PNG 打开（macOS 用 `open`），
   附一行「taste-judge 第 N 轮 total=x.x，剩余问题：……」，然后停下来等反馈。

关于审图：**图由用户本人终审**。不要派审稿 subagent、不要写评审报告；
第 5 步的预审只是把他每次都会说的话提前说掉，不替代他，也不把评审 JSON 全文贴给他。

用户提了修改意见，**先复述要改哪几页、怎么改，确认后再动手**；改完只重出改动的页（`--png 3 5`），再打开给用户看。

## 2. 画幅

- 固定 4:3、1440×1080，**不做竖屏**。
- 每页**只留一行短标题**，可以用 `<span class="acc">` 给一个关键词上强调色。
  不要小标（kicker）、不要副标题、不要讲稿块、不要页脚——要说的话写进正文 `文案.md`。
- 标题下面的白卡就是图区（1328×928），核心图占满它。四周边距已经很紧（左右 56px），别再往里缩。

## 3. 字号

- 图内任何文字 **最小 28px**（1440 画布上；手机上约 18px）。脚本低于 28px 判失败。
- 主要数字、标签、结论 **36px 以上**；公式主行 48–60px。
- 上下标是正文的 0.62 倍，所以带上下标的公式正文至少 36px（上下标才不低于 22px）。
- 放不下时**宁可少标签也要大字**：删次要刻度、合并图例、把说明挪进正文，最后才考虑拆页。
  不要缩字号去塞。
- 确实只是装饰性的小字（如角落的「示意」），可以给元素加 `data-small-ok=""`，脚本只警告不判失败；
  这个豁免一页最多用一两处。

## 4. 每页内容

- **一页只讲一件事**。一页里要讲两件事、或者自查时字号压不上去，就拆成两页。
- **对比类默认「3 行 3 个 case」**：一行一个 case，左边名字和取值，中间小图，右边一句结论（✓ / ✗）；
  最好的那个 case 用浅强调底色标出来。少于 3 个说服力不够，多于 3 个手机上挤。
- **结论紧跟着公式那一行写**，不要放到页底——读者看到公式的同时就要知道它说明了什么。
- **公式页三段式**：先给公式 → 再写推导（一两行）→ 最后代入一组具体数字算出结果。
  只代入一组，不要堆三四个例子；要多组对比就另起一页做成 3 行表格。

## 5. 公式

- 图上的公式**一律用脚本的 `M()`（SVG）/ `MH()`（HTML）排**，写法是 LaTeX 子集：
  `x_{i}^{2}`、`\frac{a}{b}`、`\sqrt{d}`、`\theta`、`\times`、`\Big(…\Big)`、`\text{softmax}`。
  效果按 LaTeX 渲染后的样子：变量斜体衬线、数字和函数名正体、真上下标、竖排分式、运算符两边自动留空。
- 全部离线排版（STIX Two / STIXGeneral / Times 依次回退），**不引 MathJax / KaTeX，不依赖 CDN**。
- `θ^(-2i/d)`、`sqrt(d)`、`a/b` 这种纯文本写法**不出现在图上**；它们只允许留在正文 `文案.md` 里
  （小红书正文不渲染公式）。
- 标题里能不放分式就不放：分式会把标题行撑高、把白卡往下挤。标题里放单个变量或 `\sqrt{d}` 这种一行高的式子即可。
- 渲染后打开 PNG 看一眼公式：分式、根号的位置是按字宽估算的，个别长式子可能需要手动挪 x。

## 6. 交付

- 图片按发布顺序编号：`png/01_总览.png`、`02_xxx.png`……。编号由页面顺序自动生成，
  调整页序只改 `@deck.page` 的先后，整套重出时旧编号的图会被清掉。
- 小红书一篇的图片张数有上限（以 App 为准），页数多时先和用户确认发哪几页。
- **正文字数上限**：小红书正文**连签名和话题标签一起 ≤ 1000 字符**。`--png` 时如果目录里有 `文案.md`，
  脚本会数字符（换行不计；口径以 App 为准）并核对「0X ·」段号和图片张数是否对得上，超了先删正文再发。
- 交付时给用户：`deck.html` 和 `png/` 的完整路径、自查表结论、文案字数。
