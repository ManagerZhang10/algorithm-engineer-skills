# 例子：多家图像编辑 API 对比

场景：同一批图片 + 同一条编辑指令，比较几家图像编辑接口「改该改的、不动不该动的」能力，用编辑框（BBox）/ mask 外的保持度和人工评审来判断。

## 1. 先选口径（二选一，不能混在一张排名里）

| 口径 | 输入 → 输出 | 保持度指标的含义 |
| --- | --- | --- |
| `strict_native`（模型本身） | 同一份 JPEG 字节、同一个原生尺寸 W×H → 各家原生输出 | 在相同输入下，模型的编辑与保持能力 |
| `delivery_pipeline`（线上链路） | 原图 → 各家各自合法的缩放 → 原生输出 → 缩放还原到原图尺寸 | 用户最终拿到的图，包含预处理和还原带来的损失 |

线上链路口径下，给每一臂再算一个「只缩放不调模型」的基线：`原图 → 该臂输入尺寸 → 该臂输出尺寸 → 原图尺寸`，把它的保持度和模型结果并排报告。PSNR 是对数量，不要直接相减。宽高比变了要分别记录 X、Y 缩放系数。

## 2. 指标的合法操作数

| 口径 | 参照 | 被评 |
| --- | --- | --- |
| `strict_native` | 冻结的模型输入字节 | 尺寸严格等于目标 W×H 的原生输出 |
| `delivery_pipeline` | 冻结的原图字节 | 还原到原图尺寸的交付图 |

缩略图、浏览器渲染、截图都不是操作数。尺寸恰好一样不代表这对产物可以比。原生输出尺寸和请求不符的样本，在 `strict_native` 下记 `invalid_output`，不要缩放后硬算分。

BBox / mask 的坐标系映射（缩放、取整、裁剪）要先冻结，并在图像边缘坐标上测一遍。

## 3. 先从官方接口文档查约束，再选尺寸

对每一个**真正要提交的路由**，查它的官方 schema 并记录：路由字符串、文档链接、查阅日期、输入方式、输出尺寸怎么控制、约束（倍数、像素总数、宽高比范围）。

先按模态过一道门：

- `image_edit`：接受源图输入，可以参与保持度对比。
- `text_to_image`：不接受源图，**不能**参与保持度对比。同一个模型家族的文生图路由不能拿来顶替编辑路由。

再按输出尺寸控制方式分类：

- `exact_dimensions`：可显式指定宽高（带倍数 / 像素数 / 宽高比约束）；
- `discrete_native_table`：按「比例 + 分辨率档」选，官方表格给出每档的精确 W×H；
- `preset_or_aspect`：只能选比例或档位，不保证精确宽高；
- `auto_only`：尺寸由服务端决定。

只有全部臂都是前两类时，`strict_native` 才可行：把各家的显式约束和尺寸表求交集，得到一组共同的原生尺寸，每张图从里面选宽高比最接近的一个；没有可用尺寸的图直接剔除并记录，不拉伸、不补边、不给不同模型选不同尺寸。只要有一臂是后两类，就写明「严格像素可比不成立」，改用线上链路口径或只做人工评审。

注意：同一个模型经不同供应商接入，尺寸控制方式可能完全不同（一家只给档位，另一家直连接口却有精确尺寸表）。分类以**你实际调用的路由**为准。

## 4. 物化输入、烟测、起量

1. 按选好的尺寸做一次预处理（EXIF 旋转、转 RGB、整图 LANCZOS 缩放、JPEG 编码），落盘。
2. `freeze_manifest.py freeze --inputs <frozen_inputs_dir> --out <run>/manifest.jsonl`。
3. 每臂烟测 1～3 张：断言 `原生输出尺寸 == 目标尺寸`，打开图看一眼；某家把请求的尺寸悄悄改掉，就把它移出严格像素指标，直到修正。
4. 起量。每条结果记 `sample_id / status / input_sha256 / params / native_w / native_h / output_path`。
5. `intersect.py` 求交集；被内容审核拦截、拒绝、尺寸不符分别计数。

## 5. 报告

- 每臂：成功数、拒绝 / 拦截数、尺寸匹配数、可计分数，与均值并列。
- 评审页上为了对齐可以统一用 `contain` 方式显示，但那只是展示，不改写原产物。
- 写明保持度指标的盲区：它只看框外，框内改坏了不计分；整图均匀调色、纹理不坏时分数偏低。必要时补局部截图。
