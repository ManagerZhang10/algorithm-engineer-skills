# 常见不公平来源（按领域）

每条都是「看起来是模型差异，其实是协议差异」。

## 通用

| 坑 | 表现 | 处理 |
| --- | --- | --- |
| 各臂各自预处理 | 一臂吃 1024 图、另一臂吃原图；一臂 prompt 多了个换行 | 预处理只做一次、落盘、哈希；结果里回填 `input_sha256` 对账 |
| 失败样本被静默丢弃 | 拒答多的臂只剩简单题，均分反而高 | 只在交集上比主指标，失败率单列 |
| 中途改配置 | 跑到一半调了 max_tokens，前后两段混在一起 | 同一臂参数套数应为 1；改了就开新 run |
| 用中转 / 转售网关 | 降质、注入隐藏上下文（输入 token 莫名多出几千）、不返回 reasoning 明细、批量 503 | 比模型走官方直连；网关单独成臂，且用直连做基线对照 |
| 拿别名当身份 | 「同一个模型」的两条路由默认参数、版本不同 | 记录真正发出去的路由字符串和响应里回传的模型版本 |
| 只看汇总指标 | 环境故障与真实难度在分数上长得一样 | 起量前读烟测输出 / 轨迹；起量后抽样看 |
| 代理指标与肉眼相反 | 均值类指标抹平高频细节 | 极端 case 逐条对照，不一致就换指标 |
| 样本重复 | 同一份字节出现多次，相当于加权 | `freeze_manifest.py` 会提示字节重复 |
| 单次随机结果 | 温度 > 0 时排名每次都变 | 每样本重复多次，报区间 |

## LLM / 文本

- system prompt、chat template、stop token 不一致；某臂自动加了安全前缀。
- max_tokens 对 reasoning 模型太小，思考吃光预算，正文为空——会被误判成「答不出」。先查空输出比例。
- 推理档位口径不同（有的叫 effort，有的是思考 token 预算，有的不暴露），统一不了就列入未对齐项。
- LLM-as-judge：裁判和某一臂同家族会偏袒；A/B 位置要随机化；裁判温度固定为 0。
- 答案抽取正则对某一臂的输出格式不友好，抽取失败被记成答错。抽取失败应单独记 `invalid_output`。

## VLM / 多模态

- 图片尺寸不同 → 视觉 token 数不同，细节题差距可能只是分辨率差距。
- 图片传 URL 时各家下载、缩放策略不同；统一用 base64 内联同一份字节。
- 有的接口会自动降采样到上限，实际看到的分辨率要从文档或响应元数据确认。

## Agent / 工具调用

- **考场和考生要分开。** 比的是模型，就让所有模型在同一个环境、同一套工具、同一个 harness 里跑，裸 API 接入；不要让某一臂带着自家 harness（自带的 CLI agent、私有工具）上场——那测的是 harness。
- 题面是唯一 prompt，环境不额外追加任何文字；环境实际收到的 query 与题面逐字节一致。
- 工具清单要由环境里实际存在的文件类型推导。文件转成 PDF / DOCX 但没给对应读取工具，考生就只能盲做。
- 可读性自检用考生手里的工具，不用你本机的库。
- 步数上限、token 上限、超时对所有臂一致；记录每臂触顶比例。
- 判分结果在不同机器 / 容器里复算应一致，不一致就记无效。

## 文生图 / 图像编辑

- 输出尺寸、质量档、输出格式（JPEG 有损）不一致。
- 图像编辑：比「模型本身」时，指标要比「模型实际收到的输入」和「模型原生输出」；不能拿原图和缩放还原后的图算保持度。详见 `example-image-edit.md`。
- 内容审核拦截率差异很大，必须单列；不要把被拦截的样本换成重跑成功的另一张。
- 多轮编辑：始终和第 0 步原图比，而不是和上一步比，否则误差不累积。

## ckpt 对比

- 评测集和训练集 / 早停用的验证集重叠。
- 不同 ckpt 的推理配置（chat template、tokenizer、量化、精度）不一致。
- 只比最后一个 ckpt，不看曲线；单个 step 的波动可能大于 ckpt 间差异，多取几个邻近 step 或报方差。
