# 工作汇报模板（通用脱敏版）

> 用途：将一段时间的工作（阶段述职、实习总结、转正或晋升）组织成一场以**业务价值、个人贡献、可验证结果与成长复盘**为主线的汇报。
>
> 使用方式：复制本文件；将所有 `[方括号]` 占位符替换为自己的内容；删除不适用的小节、说明文字和本引用块。
>
> 脱敏原则：不填写真实业务线、产品名、内部系统/模型名、策略规则、客户或用户信息、内部链接、协作者姓名、未公开数据，也不写可据此反推出业务的信息组合。用“[业务场景]”“[内部平台]”“[某类任务]”等中性表述替代。

---

## 0. 汇报信息

| 字段 | 填写内容 |
| --- | --- |
| 汇报标题 | `[姓名] 工作总结` |
| 汇报周期 | `[YYYY.MM–YYYY.MM]` |
| 汇报总时长 | `45 分钟` |
| 岗位 / 方向 | `[例如：算法工程 / 产品技术 / 数据分析]` |
| 一句话定位 | `我围绕[业务目标]，补齐了[能力缺口]，并通过[方案]带来[可验证结果]。` |

### 推荐时间分配（45 分钟）

| 环节 | 推荐时长 | 作用 |
| --- | ---: | --- |
| 个人概览 + 工作地图 | 3 分钟 | 建立背景，讲清三个项目如何构成一条主线。 |
| 核心项目 1 | 15 分钟 | 主项目；完整展示问题判断、技术深度、落地推进与业务结果。可在 10–20 分钟间调整。 |
| 核心项目 2 | 7 分钟 | 展示第二项独立能力或对主项目的关键补充。可在 5–10 分钟间调整。 |
| 核心项目 3 | 4 分钟 | 展示自动化、规模化、协作或人效等广度成果；不超过 5 分钟。 |
| 成长复盘 + 收束 | 5 分钟 | 将项目经验提炼为可迁移的方法论和后续方向。 |
| 问答 / 过渡缓冲 | 11 分钟 | 用于现场提问、项目之间过渡、展开关键证据或时间误差。 |

> 默认按 **34 分钟陈述 + 11 分钟问答 / 缓冲** 准备。若 45 分钟全部用于陈述，优先把新增时间给项目 1，其次是项目 2；不要用它扩充项目 3 或堆砌背景。

## 使用这个模板的注意事项

- [ ] **先写故事，后填细节。** 先确定共同目标、三个项目的递进 / 互补关系和每个项目的一句话结论；不要上来就搬项目文档。
- [ ] **用图讲方案。** 一图胜千言。每个项目至少一张方案全景图，项目 1 再配一张关键证据或前后对比图；图必须直接服务于本页结论。在飞书文档中可用飞书画板相关 Skill 制作可编辑图。
- [ ] **多放 case 和 demo。** 优先展示真实的输入、输出、前后对比、交互流程或演示；具体的case会让说明更有说服力。
