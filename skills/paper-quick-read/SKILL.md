# 论文速读导读

目标读者：经常读论文、但没读过这一篇、也不熟悉这个子方向的人。他想用几分钟搞清楚三件事——**这篇在跟什么麻烦较劲、为什么这个麻烦不好绕、这篇是怎么绕过去的**——并且每个具体说法都能按页码回原文核对。

这个技能分两步：脚本把 PDF 变成「带页码的全文 + 图表页图片 + 页索引」，然后**你（agent）自己读、自己写导读**。没有外部模型调用。

## 和精读类技能的分工

| | paper-quick-read（本技能） | 逐站精读 |
| --- | --- | --- |
| 用时 | 5–10 分钟读完一份导读 | 一小时以上，分多站来回对话 |
| 产出 | 一份结构固定的中文导读，具体事实带 [p.N] | 动机 → 架构 → 损失 → 数据 → 信息流 → 代码走例子 |
| 适合 | 判断值不值得细读、组会前快速了解、横向扫几篇 | 要真正吃透一篇、要对着代码理解 |

用户要逐站精读、对照官方代码讲解时，推荐第三方技能 [skJack/kelip-paper-reading](https://github.com/skJack/kelip-paper-reading)。速读后用户想深入某一节，也可以建议换它。

## 第一步：抽取

```bash
python3 scripts/extract_paper.py <arXiv ID | arXiv 链接 | PDF 直链 | 本地 PDF> [--out DIR]
```

- 依赖只有 PyMuPDF：先 `python3 -c "import pymupdf"`（旧版是 `import fitz`）。缺了就提示用户 `pip install pymupdf`，建议装进虚拟环境，不要擅自往系统 Python 里装。
- 默认输出到 `./paper-quick-read/<id>/`；arXiv 下载前固定等 3 秒，429/5xx 退避重试；`paper.pdf` 已存在就复用，不重复下载。
- arXiv 带版本号（`2505.11493v2`）就按该版本下载，不带就是最新版。导读开头写明读的是哪一版。

产物：

| 文件 | 内容 |
| --- | --- |
| `text.txt` | 全文，每页前有一行 `===== PAGE N =====` |
| `pages/pNNN.png` | 含图或含图注/表注的页面渲染图（110 dpi）；扫描件每页都渲染 |
| `index.json` | 标题、页数、`scanned`、`figure_pages`、`caption_pages`（如 `"Figure 2": 4`），以及每页的 `line_start`/`line_end`/`captions`/`image` |

脚本 stdout 会打印标题、页数、字符数和图表页列表——先看这几行确认抽对了论文。之后还想看某页原图（比如公式页），用 `--render 5,9` 或 `--render 3-6` 补渲染，不会重抽全文。

## 第二步：读

**必须读完整篇正文，不能只凭摘要写。** 但要按块读，不要一口气把全文塞进上下文：

1. 先读 `index.json`：页数、`caption_pages`（哪张图表在哪页）、每页行号区间。
2. 按页的行号区间分块读 `text.txt`（每次几页，约 200–300 行）。顺序：摘要和引言 → 方法 → 实验 → 结论 → 附录（附录可以先扫图注和小标题，用到时再细读）。
3. 边读边记一张自己的笔记：论文类型、要解决的麻烦、各模块名字和所在页、关键数字和所在页/表、局限、future work。
4. **只看你要引用的那几页 PNG**：总览图、要点出编号的图表、要报数的结果表。不需要把所有图表页都看一遍。表格数字以 PNG 为准——纯文本抽取常把表格行列打散。
5. `scanned: true` 表示抽不出文字（扫描件），只能逐页看 PNG；这时在导读开头说明是看图读的。

## 第三步：写

先确定模式：用户没指定就用**提纲版**；说「扫一眼」「更短」「速读版」就用**速读版**。然后读对应的骨架文件，严格照它写：

- 提纲版：[references/outline.md](references/outline.md)
- 速读版：[references/speed.md](references/speed.md)

下面的通用规则两版都适用。导读写进 `<输出目录>/guide_outline.md` 或 `guide_speed.md`，同时在回复里给出全文。输出简体中文，直接从第一节开始，不复述规则、不写阅读过程、不寒暄。

### 页码引用

- 正文里凡是具体数字、具体做法或容易被质疑的事实，在句末附一次位置：`[p.7]`，有图表时写 `[p.7, Table 3]`。**一个段落最多附一次，不要每句都附。**
- 页码是 PDF 的物理页（即 `===== PAGE N =====` 的 N），不是论文排版上印的页码；两者对不上时以 N 为准。
- **指认图表编号不受「一段一次」限制**，那是读者按图索骥的入口，该点就点。图表在哪页查 `caption_pages`，**只写你确实看到的编号**——编号错了比不写更糟，拿不准就只描述这张图画的是什么。
- 开头的「一句话概括 / 一句话总结」不附位置。

### 可读性规则

- **要能扫读，也要能读懂。** bullet 严格照这个形状写：**加粗的第一句就是这一条的论点，本身是完整的一句话。** 接着用一到两句话解释为什么，或者具体怎么做。到此为止。
- 加粗部分是论点，不是标签。「**数据清洗：**」是标签，「**先把训练数据筛干净。**」才是论点。**只读所有加粗句就应该能串出整篇的主线。**
- **每条最多三句：加粗一句 + 解释一到两句。** 写到第四句就该砍了；不要在一条里塞进背景、动机、做法、效果和局限。
- **不要一上来就穷举。** 这是导读，不是综述。宁可少讲一个点，也不要把一个点讲成一段。
- **先说人话，再给名字。** 论文自造的概念、缩写和指标，第一次出现时先用日常语言说清它指什么，再在括号里给论文的叫法和缩写，例如「衡量一句提示词究竟给模型带进来多少画面信息（论文称 Grounded Perplexity Gain，GPG）」。此后可以直接用缩写。**绝不在解释之前先甩出缩写**，也不要整段照抄英文行话。
- **不认识的缩写不要猜。** 只解释论文明确写出全称或给过定义的缩写；没展开的照抄原文，写「论文未说明该缩写的全称」。把 DPO 猜成「差分隐私」这类错误比保留缩写严重得多。
- **少给数字。** 只有数字本身就是结论时才写。公式系数、学习率、层数、参数量、消融表逐项数值一律不进正文，**绝不整段罗列基准分数**。
- **不要写 LaTeX。** 公式用一行纯文本，例如「最终奖励 = 任务奖励 - 惩罚系数 × 超出预算的部分」，先说直觉再说变量。公式默认不写，全文最多 1 个；**但如果论文的核心贡献本身就是一个公式、一条损失或一条更新规则，就一定要写出来。**
- **同一个意思只说一遍。** 不要中文、英文、缩写三件套连着摆。
- **自检：** 把所有括号、数字和英文缩写盖住，读者仍应能复述这篇论文在做什么。做不到就重写。

### 证据与防幻觉规则（与可读性冲突时以本节为准）

- **只依据这份 PDF。** 下结论前交叉核对摘要、引言、方法、实验和附录，不要只凭摘要补全方法细节，也不要用你对这篇论文或这个领域的记忆补内容。
- 位置无法确认时，写「论文未说明」或直接省略该细节，**绝不按领域惯例猜**模型版本、模块结构、超参数或数据规模。
- 明确区分**论文明确说明**、**直觉解释**和**从结果作出的推断**。类比只用来帮助理解，不得伪装成论文事实；在段落里可以用「论文报告……」和「这意味着……」把两者拆成两句。
- 写了「某方法比某方法强」，就紧跟一句边界：在哪些基准、什么评测设置、谁来打分的条件下成立。
- 特别复核容易混淆的概念：人工标签与派生指标、平均与拼接、冻结的原始权重与可训练适配器、独立任务与联合输出、训练流程与推理流程。
- 正文、公式和表格互相冲突时直接指出冲突，写清两处分别在哪，不要替它挑一个版本。
- **贡献分三层写**（两版都要体现）：论文明确宣称的贡献 / 实验真正支持住的部分（有对照或消融撑着的）/ 没被单独验证、无法拆开归因的部分（这一层必须明说是你的判断）。
- 不生成「值得追问的问题」「延伸问题」「下一步建议」、推荐问题或邀请继续提问的结尾，只总结论文本身。
- **写完整比写短重要。** 所有该有的章节都要写完，绝不写到一半停下；篇幅靠「每条三句以内、不穷举次要实验、不罗列分数」压下来，不靠中途收手。

## 第四步：交付前抽查

写完不要直接交。按下面的顺序核一遍，有错就改，改完再交：

1. **页码抽查**：从导读里挑出所有带数字的句子和至少 5 条带 [p.N] 的句子，回到 `text.txt` 对应页（表格数字看 PNG）逐条确认：这一页真的支持这句话吗？数字、单位、比较对象、实验设置都对吗？页码对不上就改页码，内容对不上就改内容或删掉。
2. **图表编号抽查**：每个 Figure/Table 编号都在 `caption_pages` 里查到，且所在页和你写的一致。
3. **无中生有检查**：有没有论文里不存在的模块、实验、动机或结论？有没有把你的推断写成了论文结论？
4. **结构检查**：按所选模式骨架文件末尾的收尾检查逐条过。

交付时在回复开头一行写明：论文标题、读的版本（arXiv ID 或文件名）、模式、导读文件的绝对路径。

## 可选：浏览器里用

同作者有一个配套的 Chrome 扩展 [chrome-paper-reader](https://github.com/ManagerZhang10/chrome-paper-reader)：在 arXiv / PDF 页面上一键生成同样两版导读，流式输出，可接着追问。它需要本地起一个服务并配置你自己的多模态模型 API Key；本技能是它的无服务器、无 Key 版本，由 agent 自己读。
